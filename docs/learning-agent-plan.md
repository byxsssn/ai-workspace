# AI Workspace 学习 Agent：产品与实现计划

日期：2026-10-29（北京时间）

状态：计划已采用，2026-10-30 已实现第一阶段的后端读取接口、演示数据与检查脚本。
FastAPI 三章已通过真实读取验证；Notion 读取器已通过模拟响应测试，真实授权联调待配置。
未实现教学 Agent、学习页面或 Notion 写回。操作说明见 [学习资料读取](learning-sources.md)。

## 1. 产品定位与首版目标

在现有 AI Workspace 中增加“学习模式”：根据用户已有进度，读取选定的官方文档，开展讲解、答疑和小练习，整理学习笔记，经用户确认后保存到 Notion，下次进入时继续学习。

首版定位为“基于官方文档、记得学习进度的 FastAPI 学习助手”。学习知识是主要用途，项目实践是可选的巩固方式；不要求每次学习都转换成求职任 务。

成功标准是一段完整体验：进入 → 续接进度 → 查阅官方章节 → 对话学习 → 整理笔记 → 确认保存 → 重新进入后续接。

继续使用当前仓库、账号体系、前端、数据库和部署。新增独立学习模块，不重新搭建一个完整应用。

## 2. 一次学习的用户流程

以 FastAPI 的 Async Tests 为演示主题：现有 Notion 记录曾将它列为下一步，但旧记录不能证明用户今天仍未学习；开始时允许用户确认或调整章节。

1. 用户选择“继续学习 FastAPI”，也可以从首版章节列表选择复习内容。
2. 助手读取 Notion 当前属性、相关笔记和未解决问题，显示本次选择的章节与依据。
3. 助手读取对应官方页面，保留章节标题、来源 URL、获取时间和可识别的版本信息。
4. 用户可以要求逐段讲解、解释概念、追问代码或给一个例子。回答区分官方依据、助手解释和自行构造的示例；引用能打开对应来源。
5. 用户可选择一道小练习或用自己的话解释概念。助手反馈理解中的问题；首版不执行用户代码，不声称未运行的代码已测试通过。
6. 点击“整理本次学习”，生成可编辑笔记，以及拟更新的当前进度和下一步。
7. 点击“保存本次学习”，后端执行已确认的变更，读回验证并提供 Notion 链接。
8. 重新进入时读取当前学习状态，并结合此前会话继续。未保存草稿仍在应用中，不冒充已同步到 Notion。

## 3. 首版范围

| 包含 | 范围限制 |
| --- | --- |
| 官方文档学习 | 一门技术，先支持下列 3 个章节；最多扩为 5 个 |
| 结合个人进度 | 绑定现有学习库中 FastAPI 对应的记录 |
| 教学对话 | 讲解、追问、举例、一个小练习及反馈 |
| 来源展示 | 标题、URL、相关章节；缺乏依据时说明 |
| 学习笔记 | 自动生成草稿，用户可编辑，一次确认保存 |
| 进度查看 | 沿用 Notion 现有属性，应用展示读取到的状态 |
| 再次学习 | 恢复会话，读取最新记录，允许选择继续或复习 |
| 演示 | 虚构样例数据与少量官方章节，可不连接私人 Notion 展示 |

预选章节：

- [Testing](https://fastapi.tiangolo.com/tutorial/testing/)
- [Async Tests](https://fastapi.tiangolo.com/advanced/async-tests/)
- [Testing Dependencies with Overrides](https://fastapi.tiangolo.com/advanced/testing-dependencies/)

这些章节构成一个小型测试专题。先展示预选目录；输入对应官网链接也可定位到章节。首版不承诺任意网站或任意 FastAPI 页面都能立即导入。

暂缓：全站抓取、任意网页问答、自动生成完整课程、多 Agent、语音、在线代码执行、复杂考试评分、向量数据库、MCP、日历提醒、岗位匹配、多用户 Notion OAuth 和跨平台双向同步。

## 4. Notion 保存结构

复用现有“技术学习进度”数据库：一门技术一行，正文存学习结论与记录。第一版不新建另一套学习数据库，也不重建已有长目录。

| 位置 | 保存内容 | 更新规则 |
| --- | --- | --- |
| 当前进度 | 实际读到的章节、节或明确完成的内容 | 根据本轮实际内容提出变更，用户确认 |
| 下一步 | 一个明确的下一步或待解决问题 | 可以调整，保留用户最终选择 |
| 学习状态 | 沿用现有选项，如“学习中” | 不因结束一轮对话自动改为“已完成” |
| 掌握程度 | 沿用已有自评 | 首版不自动提升或降低，不用聊天次数推断 |
| 成果链接 | 对应练习、代码或测试结果的链接 | 仅保存用户提供并确认的真实链接，不能凭链接证明个人掌握 |
| 主题页面正文 | 本次简短笔记、来源、练习反馈、疑问 | 在固定学习记录区追加，保留其他内容 |

每次学习记录的建议格式：

- 日期与主题／章节。
- 本次实际覆盖内容：3—5 条简短结论。
- 官方来源：页面及相关章节。
- 练习与反馈：做了什么、结果来自用户说明还是实际可核查材料。
- 仍未解决的问题。
- 下次建议。
- 用于防重复保存的学习记录 ID。

正文只保留本次记录及历史证据；全局“当前进度、下一步”以属性为准。已有章节复选框仅表示阅读情况，首版可保留原样；可靠映射章节位置后，再支持确认勾选特定项。

不能把“打开过页面”“聊过这个概念”“AI 生成了代码”直接当作掌握证据。不展示没有清晰分母和评价依据的“掌握百分比”。

## 5. 自动保存与用户确认

- 应用自动保存成功接收的对话、学习会话和草稿；失败的运行有明确状态。
- 用户结束学习时，自动整理笔记草稿，展示“保存本次学习”操作。
- 确认界面同时展示笔记、目标 Notion 页面和属性前后变化；用户无需逐字段点击确认。
- 用户确认后由后端写入。模型可以提出更新，不能自行完成用户确认，也不能任意修改其他页面。
- 写回后读回核验；只有确认写入成功才显示“已保存到 Notion”。
- 超时但结果不明确时显示“保存结果待核查”；先查询目标记录，避免直接重试产生重复笔记。
- 将来可提供用户主动开启的“自动归档笔记”选项；掌握程度变更仍保持可见、可修改。首版不做后台自动写入。

## 6. 数据边界与技术方案

| 数据 | 主要来源／存放位置 |
| --- | --- |
| 技术知识依据 | 选定官方文档；不是模型记忆或个人学习状态 |
| 学习进度、长期笔记 | Notion |
| 对话、运行记录、草稿、确认操作 | 现有 PostgreSQL |
| 文档缓存 | 应用的可失效缓存，带来源、获取时间与内容哈希 |
| 测试与公开演示数据 | 固定的虚构学习记录，不包含私人 Notion 内容 |

保留 FastAPI、SQLAlchemy、PostgreSQL、React 和现有部署；新增单个 LangChain create_agent、官方文档读取模块和 Notion API 接入模块。

建议的最小模型工具：

1. get_learning_state(topic_id)：返回当前属性、必要笔记、来源链接和读取时间。
2. read_official_doc(section_id)：读取服务端目录中已批准的官方章节，返回正文和来源信息。
3. propose_learning_update(session_id, note, progress_changes)：校验并保存更新草稿，不执行 Notion 写入。

固定章节目录由服务端提供，不需要另造一个搜索平台。模型决定何时查进度、读取哪章、是否需要补充资料或追问。权限、可写字段、步数和超时由普通代码限制。

apply_learning_update(action_id) 是用户确认后的业务接口，重新检查登录身份、目标页面和草稿版本，不作为可随意执行的模型工具。

Notion 请求集中在一个模块，对应用返回统一的学习记录结构，不把 Notion 原始 JSON 和字段映射散布到各处。字段映射、页面与 data_source 标识放在连接配置中，私有标识和凭据不写进公开样例。

先使用仅绑定本人账号的 Notion 内部连接；其他账号只能使用自己的连接或演示数据，不能共享私人工作区权限。当前聊天中的 Notion 连接不会自动赋予此应用访问权限。未来支持其他用户时再增加 OAuth。

实现前用一个模型验证工具调用、必要的结构化输出与错误处理，并检查新增依赖和 Python 3.14 的兼容性。现有 Responses 文本适配器不能未经验证直接当作 LangChain 工具模型适配器。

## 7. 来源、故障与写回可靠性

### 官方文档

- 用章节 ID 映射受控的 HTTPS 官方 URL，抓取有时间、响应大小和次数限制；重定向目标也校验。首版不开放任意 URL 抓取。
- 提取正文、标题层级和代码块，去除导航噪声；文档内容作为资料，不作为执行指令。
- 回答引用只能使用实际获取的来源。引用存在不等于论述正确，仍需人工检查代表性答案。
- 记录获取日期与可识别版本；无法确认版本就写未知。获取时间不等于发布时间，也不保证官网示例与项目锁定版本完全匹配。
- 允许短期缓存和手动刷新。使用旧缓存时注明时间；没有可用内容时说明读取失败，不伪造“刚查过官网”。

### Notion 与执行

- 处理分页、权限不足和限流；连接失败时保留草稿，不谎报同步成功。
- 每次保存有稳定 action_id，本地唯一约束、并发执行锁和远端可核查记录标记共同防重；不宣称跨系统事务或绝对只执行一次。
- 写入前重读相关属性和笔记目标，检测与提案基线的变化；发现冲突时保留草稿、刷新预览，不静默覆盖。普通 API 检查不能消除所有并发窗口，首版按个人串行保存设计。
- “追加笔记”和“更新属性”可能部分成功，分别记录阶段并核查已完成步骤；失败恢复时不能再次追加同一笔记。
- 当前 ChatService 在模型生成期间保持读取事务。新增学习运行采用“短事务读取／登记 → 释放数据库连接 → 执行模型及工具 → 短事务保存结果”，避免把外部调用包在长事务里。
- 同一学习会话同时只允许一次运行；限制工具次数、累计文档量和执行时长。进程中断的运行显示中断／待核查，首版不做自动恢复长任务。
- 模型密钥、Notion 凭据和学习记录都按登录用户隔离；密钥不进入模型上下文、工具结果、普通日志和运行轨迹。

## 8. 页面设计

在已有工作区增加“学习”入口，先用一个页面：

- 左侧：学习主题、当前进度、上次问题、3 个可选章节。
- 中间：教学对话、代码示例、官方引用、简短的工具执行状态。
- 下方或侧边：本次笔记草稿、进度变更预览、“保存本次学习”、保存结果和 Notion 链接。

先完成可读的代码块和来源链接，允许非流式回答。流式输出、漂亮仪表盘、图谱和复杂编辑器不作为首版完成条件。

## 9. 交付顺序与时间预算

用户每周约 10 小时，仍预留约 2 小时给求职；项目预算约 8 小时／周，已经包含针对性学习、亲自使用和验证。

| 顺序 | 产出 | 验收 | 粗估投入 |
| --- | --- | --- | --- |
| 1. 接入验证 | 3 章文档目录、正文读取、Notion 学习记录读取、虚构样例 | 正文和代码能读到；权限失败可解释；样例不依赖私人工作区 | 6—8 小时 |
| 2. 教学 Agent | 三个工具中的读取能力，讲解、追问、引用、小练习 | 能结合已有进度；查不到依据时说明；不自动更新状态 | 8—10 小时 |
| 3. 学习页面与续接 | 接入已有页面、保存会话、查看来源和上次疑问 | 刷新后能接着学；用户之间隔离 | 6—8 小时 |
| 4. 笔记与进度保存 | 草稿、编辑、确认、Notion 写入及读回核查 | Notion 中可查看；重复点击、部分失败和结果未知有明确处理 | 10—12 小时 |
| 5. 评测与展示 | 固定案例、修复、README 使用说明和 3 分钟演示 | 正常学习与失败案例均能复现 | 6—10 小时 |

合计约 36—48 小时，按当前投入约 5—6 周；这是范围估算，不是交付保证。前 2—3 周争取先有可用的只读学习版本。文档解析或写回耗时超出预期时，缩减章节和界面装饰，不删除来源校验、用户隔离和保存结果核查。

每个阶段选择一个小模块由本人负责理解、修改、测试并说明结果；可继续使用 AI 辅助，不要求全部手写。新增亲自验证的证据之后再更新简历。

## 10. 验收与简历展示

固定 10—12 个小场景，记录实际结果，不预先填写成功率：

1. 读取现有进度并续接指定章节；允许用户纠正过时记录。
2. 围绕官方章节追问，回答引用能打开、论述有依据。
3. 区分官方示例、助手补充例子与用户提交的代码。
4. 文档不可访问或只有旧缓存时，正确说明来源状态。
5. 用户仅阅读或聊天时，不自动提高掌握程度。
6. 草稿可编辑，未经确认不写入 Notion。
7. 保存后，Notion 属性和笔记与确认内容一致，重新进入可续接。
8. 双击确认或网络重试，不新增重复记录。
9. 写入超时或部分成功时，先核查再恢复，不显示虚假成功。
10. 用户在 Notion 修改进度后，旧提案不静默覆盖新值。
11. 不同账号不能读取对方连接、会话、草稿或学习记录。
12. 达到工具次数／时间限制时结束运行，保留可理解的错误状态。

机械约束用自动化测试；教学准确性、解释清晰度和来源是否真正支持答案用少量人工评审。记录完成情况、错误类型、耗时和供应商实际返回的 Token 用量，未知用量保持未知。

3 分钟演示：继续学习 → 查看官方依据并追问 → 回答一道练习 → 编辑笔记并保存 → 打开 Notion 确认 → 重新进入续接。另准备一个读取失败或重复保存的短案例。

项目成果可以围绕“官方文档检索与教学对话、学习状态管理、受控工具执行、可靠写回、评测与失败处理”描述。具体效果和个人贡献以实现后验证结果为准。

## 11. 后续扩展门槛

- 首个专题真实使用顺畅后，扩展 Python／SQLAlchemy 等技术与更多官方页面。
- 出现跨章节检索困难，再评估全文检索、切分、Embedding 和 pgvector。
- 接入多个工具服务或需要共享自定义工具时，再引入 MCP。
- 用户需要长任务暂停／恢复或更复杂确认流程时，再深入 LangGraph 持久化能力。
- 岗位差距分析、学习计划、复习安排和项目成果归档，作为已有学习流程稳定后的独立增量。
